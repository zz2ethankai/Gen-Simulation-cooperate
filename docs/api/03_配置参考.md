## 1. Task YAML

入口：`workflows/simbox/utils/task_config_parser.py::TaskConfigParser.parse_tasks()`（task_config_parser.py:31）；执行：`workflows/simbox_dual_workflow.py::SimBoxDualWorkFlow` 和 `workflows/simbox/core/tasks/banana.py::BananaBaseTask`。

文件顶层必须是 `tasks:` 列表。解析器不过滤未知字段：未知字段保留在 `task.cfg` 中，只有对应代码分支读取时才生效。要写出能直接运行的 task，需要同时满足：

- `arena_file` 指向可读取的 Arena YAML。
- `asset_root` 能解析 object、fixture、texture、camera 文件中的相对路径。
- `robots`、`objects`、`regions`、`cameras`、`skills`、`data` 键存在；scene-only task 可用空列表。
- `skills` 非空时，skill 引用的 robot、controller、object 名必须存在。
- `regions` 非空时，`object` 和 `target` 必须能在 task objects、arena fixtures、robots 或 cameras 中找到。

### `skills`

`skills` 的 YAML 嵌套结构固定为 `<robot_name> -> <controller_name> -> skill list`，legacy 顺序模式与 DAG 模式的写法见 02 第 B1、B2 节。要点：

- `skills[]` 的每个元素是一个 phase；legacy 模式下后一个 phase 等前一个全部完成。
- `<robot_name>` 必须匹配 `robots[].name`；`<controller_name>` 常见为 `left` / `right`，移动底盘导航用 `base`。
- 同一 controller 下的 list 是顺序队列；同一个 phase 内多个 robot/controller 可并行推进。
- 任意 skill 写了 `id` 或 `depends_on` 时整个 task 进入 DAG 模式。显式 `id` 必须唯一；旧版嵌套 skill 若省略 `id`，workflow 编译器会按 `legacy:<robot>:<controller>:p<phase>:s<sequence>:k<skill>:<name>` 生成稳定 ID，并按原 phase/sequence 顺序补充无环依赖。`depends_on` 仍必须是 list（省略时默认为空）；显式 ID/依赖不会被改写。
- 只加载 scene 不执行技能时写 `skills: []`。

Skill 注册名来自 `workflows/simbox/core/skills/__init__.py` 中的类名转小写并以下划线分词（`Goto_Pose -> goto_pose`）。一览表如下：

| 注册名 | 主要功能 |
| --- | --- |
| `pick` | 基于抓取标注执行标准抓取，支持调试快照输出。 |
| `manualpick` | 在标准抓取上增加手工姿态/位移修正。 |
| `dexpick` | 使用 `dexpick_pose.yaml` 里的离散抓取位姿执行抓取。 |
| `dynamicpick` | 面向动态目标的抓取，带时间偏置和运动预测。 |
| `failpick` | 故意偏移抓取点，生成失败抓取轨迹。 |
| `pick_plan_probe` | 只规划不执行，把结构化候选写入 JSON；validation-only skill。 |
| `place` | 通用放置 skill，支持垂直/水平放置和多种成功判定。 |
| `dexplace` | 基于物体/容器几何范围的放置。 |
| `move` | 驱动末端带动物体向参考物体移动。 |
| `goto_pose` | 直接到指定末端位姿。 |
| `track` | 采样一组路点，驱动末端按路点追踪。 |

| `navigate` | 本地 A* 规划 + Waypoint P 控制器驱动移动底盘导航（ROS-free）。 |

## 2. Arena YAML

Arena 文件由 `task_cfg["arena_file"]` 读取，存入 `cfg["arena"]`。Arena 只描述静态场景底座和 fixture；`objects`、`regions`、`robots`、`cameras`、`skills` 属于 Task YAML。一个 arena 能否加载取决于引用它的 task 的 `asset_root` 能否解析 fixture 的 `path` 和 texture 目录。

| `update_freq` | `int` | `BananaBaseTask.individual_reset()` | scene-pair 刷新。 |
| `involved_scenes` | `str`, comma-separated | `update_scene_pair()` | 场景对随机化；当前实现期待逗号分隔字符串。 |

| 配置块 | 消费入口 | 字段详见 |

`config_contract.py` 的分组语义：

| 常量 | 值 | 位置 |
| --- | --- | --- |
| `PHYSICS_SCHEMA_SKILLS` | `{pick, place}` | config_contract.py |
| `VALIDATION_ONLY_SKILLS` | `{pick_plan_probe}` | config_contract.py |
| `NON_MANIPULATION_SKILLS` | `{navigate, observe_hold}` | config_contract.py |
| `DIRECT_EXECUTION_MODE` | `direct_execution` | config_contract.py |
| 碰撞世界模式常量 | `physics_schema` / `passthrough` | config_contract.py |

解析规则（`resolve_skill_collision_world_mode()`，config_contract.py:37-50）：

- `navigate`、`observe_hold` 强制 `passthrough`，不建碰撞世界。
- `pick`、`place`、`pick_plan_probe` 和其他操作 Skill 使用 `physics_schema`。
- `heuristic__skill` 的 `mode: home` 和 `home` Skill 通过 `direct_execution` 直接下发关节动作，不进入上述碰撞世界解析。

`resolve_collision_world_mode()`：返回 `physics_schema`；旧的 world selector 只用于发出弃用警告，不会选择第二个运行时世界。

`validate_planning_contract()`（config_contract.py:129-185）校验：

- Physics-schema `pick` / `place` 的对象数量。
- 同一 phase 内 left 和 right 同时有操作类 skill（`UNSUPPORTED_CONCURRENT_MANIPULATION`）。
- `pick_plan_probe` 缺 `metadata.workspace_probe` 或对象数不为 1。
- `pick` 对象数不为 1、`place` 对象数不为 2。

skill 侧消费：`pick.py:566-568` 从 `task.cfg["planning"]["pick_place"]` 读 `terminal_step_m`、`max_terminal_distance_m`；`place.py` 读 `place_terminal_*` 系列（默认值见 01 第 6.1 节）。
