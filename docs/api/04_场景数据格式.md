# assets_addition 场景数据格式

> 核对日期：2026-08-13；代码基线：527f31b

## 1. 适用范围

本文档说明 `InternDataAssets/assets/assets_addition` 场景资产包的目录格式、字段结构及生成方式。该目录与 `workflows/simbox/assets/assets_addition` 内容互为镜像，下文以镜像目录中的 `file_2` 为实测样本。

数据按场景分目录存放，共 10 个场景：`file_2` ~ `file_11`。每个场景目录是独立分发单元，包含场景 USD、布局清单、优化报告和贴图。

## 2. 目录结构（实测）

`assets_addition/` 根目录：

```text
assets_addition/
├── .gitattributes
├── file_2/ ... file_11/      # 10 个场景目录
├── render_image/             # 各场景顶视渲染图汇总
└── render_script/            # 渲染脚本与参数说明
```

`file_2/` 场景目录：

```text
file_2/
├── package_manifest.json     # 场景包布局清单
├── asset_optimization_report.json
├── empty_room.usd            # 空房间（无家具）
├── scene.usd                 # 整场景（引用拆分资产）
├── assets/
│   ├── arena/                # 静态家具拆分 USD，5 个
│   └── task_obj/             # 可操作物体
│       ├── adjustable_floor_lamp_0_id236/
│       │   └── Aligned_obj.usd, Aligned_obj.obj
│       ├── ...               # 共 35 个地面物体目录
│       ├── small_usd/        # 175 个小物体目录，结构与上同
│       └── textures/         # 场景贴图副本
├── render_image/
│   └── top_down.png          # 2560x1440 顶视渲染图
└── textures/                 # 墙面、地面和材质贴图
```

实测计数与 `package_manifest.json` 一致：`arena_count=5`、`task_obj_floor_count=35`、`task_obj_small_count=175`。

各目录约定：

- `assets/arena/`：静态家具 USD，命名 `file_<id>__<object>_<n>_id<m>.usd`（如 `file_2__three_seat_sofa_0_id49.usd`）。目录内混有少量 `*_texture.png` 和 `textures/` 子目录。
- `assets/task_obj/`：地面物体每对象一个目录，内含 `Aligned_obj.usd`（主文件）与 `Aligned_obj.obj`。`small_usd/` 下的小物体目录结构相同。目录顶层另有 7 个散落的 `*_texture.png`，不属于任何对象目录。
- `textures/`：三类 PNG——`floor_<room>.png`、`wall_<room>.png`（按房间命名）、`file_<id>_material_<n>_<hash>.png`（材质导出贴图）。

## 3. package_manifest.json

场景包布局清单，每个场景目录一份。顶层字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `scene` | string | 是 | 场景名，如 `file_2` |
| `arena_count` | number | 是 | arena 静态资产数 |
| `task_obj_floor_count` | number | 是 | 地面 task object 目录数 |
| `task_obj_small_count` | number | 是 | 小 task object 目录数 |
| `layout` | object | 是 | 布局路径，见下表 |

`layout` 字段：

| 字段 | 类型 | 必填 | 值（实测） |
| --- | --- | --- | --- |
| `empty_room` | string | 是 | `empty_room.usd` |
| `full_scene` | string | 是 | `scene.usd` |
| `arena_assets` | string | 是 | `assets/arena` |
| `task_assets` | string | 是 | `assets/task_obj` |
| `task_asset_file` | string | 是 | `Aligned_obj.usd`，task object 目录内的主文件 |
| `task_asset_layout` | string | 是 | `per_object_directory`，每对象一个目录 |
| `small_task_asset_layout` | string | 是 | `per_object_directory` |

## 4. asset_optimization_report.json

资产优化报告，记录纹理和 USD 的优化前后对比。顶层字段：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `scene` | string | 是 | 场景名 |
| `textures` | array | 是 | 纹理优化记录，file_2 实测 184 项 |
| `usd` | array | 是 | USD 优化记录，file_2 实测 214 项 |

`textures[]` 项（5 个字段）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `path` | string | 纹理路径（源机器绝对路径，仅作记录） |
| `before_bytes` | number | 优化前字节数 |
| `after_bytes` | number | 优化后字节数 |
| `before_size` | array | 优化前像素尺寸 `[w, h]` |
| `after_size` | array | 优化后像素尺寸 `[w, h]` |

`usd[]` 项（5 个字段）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `path` | string | USD 路径（源机器绝对路径，仅作记录） |
| `shader_defaults` | number | 应用 shader 默认值的材质数 |
| `mesh_count` | number | 网格数 |
| `decimated_meshes` | number | 被减面网格数 |
| `meshes` | array | 网格明细，个别项为空数组 |

`meshes[]` 项（7 个字段）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `path` | string | 网格 prim path，如 `/Asset/Geometry/geom_0_0_geometry_0` |
| `before_points` | number | 优化前顶点数 |
| `after_points` | number | 优化后顶点数 |
| `before_faces` | number | 优化前三角面数 |
| `after_faces` | number | 优化后三角面数 |
| `decimated` | boolean | 是否被减面 |
| `skip_reason` | string | 未减面原因，实测取值 `has_uv`、`below_threshold` |

## 5. render_script/ 与 render_image/

`render_script/` 位于 `assets_addition/` 根目录，不属于单场景：

- `render_isaac_scenes.py`：Isaac Sim 渲染脚本
- `run_render.sh`：启动脚本，默认 `ISAAC_SIM_ROOT` 为 `isaac-sim-4.2.0`，渲染对象为 `scene.usd`
- `render_multiview.log`：渲染日志
- `README.md`：渲染参数说明

脚本可用参数：

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `--scenes-dir` | 必填 | 场景根目录 |
| `--output-dir` | 必填 | 输出目录 |
| `--usd-name` | `scene.usd` | 渲染的 USD 文件名 |
| `--views` | `top_down` | 视角列表，见下 |
| `--width` / `--height` | `2560` / `1440` | 分辨率 |
| `--spp` | `256` | 每像素采样 |
| `--total-spp` | `2048` | 每视角总采样 |
| `--warmup-frames` | `48` | 预热帧数 |
| `--settle-frames` | `144` | 稳定帧数 |
| `--hdri-path` | 无 | HDRI 环境贴图 |
| `--camera-distance-scale` | `1.0` | 相机距离缩放 |
| `--filename-mode` | `legacy` | `legacy` / `multiview` |
| `--capture-timeout` | `180.0` | 单视角捕获超时（秒） |

脚本内置 6 种视角规格（`VIEW_SPECS`）：`top_down`、`hero`、`front_right`、`rear_left`、`low_angle`、`top_oblique`。

输出命名：`legacy` 模式且单视角时输出 `<scene>_isaac_realistic.png`，多视角时输出 `<scene>__<view>.png`。

`render_image/` 位于 `assets_addition/` 根目录，含 10 张 `file_<id>__top_down.png`（2560x1440，顶视）。每个场景目录内另有 `render_image/top_down.png`，与汇总图同内容。README 中记录的 `hero`/`front_right`/`rear_left`/`top_oblique` 多视角参数来自 Benchmark_1.0 历史导出，当前 `assets_addition` 实际产出只有 `top_down` 单视角。

## 6. 生成脚本与参数

`scripts/generate_assets_addition_scene_configs.py` 将场景包转换成 SimBox 的 arena yaml 和 scene-only task yaml。

环境要求：脚本会解析 `scene.usd` 的 root layer，需要 `pxr` / `usd-core`，用 `anygrasp` 环境运行。缺少 `pxr` 时脚本报错退出。

常用命令：

```bash
# 生成单个场景
/home/dyf/miniconda3/envs/anygrasp/bin/python scripts/generate_assets_addition_scene_configs.py \
  --scene-dir workflows/simbox/assets/assets_addition/file_2 --overwrite

# 批量生成全部 file_* 场景
/home/dyf/miniconda3/envs/anygrasp/bin/python scripts/generate_assets_addition_scene_configs.py \
  --all --overwrite
```

主要参数：

| 参数 | 说明 |
| --- | --- |
| `--scene-dir` | 单个场景目录 |
| `--all` | 处理 `--addition-root` 下所有 `file_*` |
| `--mode` | `split`（默认）/ `full-scene` |
| `--exclude-small-task-objects` | task yaml 中排除 `assets/task_obj/small_usd/*/Aligned_obj.usd` |
| `--include-floor-plane` | arena yaml 中增加名为 `floor` 的合成平面 |
| `--output-arena-dir` / `--output-task-dir` | 输出目录，默认 `workflows/simbox/core/configs/arenas/addition/` 与 `tasks/addition/` |
| `--overwrite` | 覆盖已有文件 |
| `--dry-run` | 只打印不写文件 |
| `--max-episode-length` | 任务最大回合数 |

`split` 模式语义：

- arena yaml 加载 `empty_room.usd` 与 `assets/arena/*.usd`。
- task objects 只从 `scene.usd` 收集 `assets/task_obj/...` reference，arena 中的不可动物体不会重复进入 task yaml。`small_usd` 引用默认包含，可加 `--exclude-small-task-objects` 排除。
- 位姿来源：`xformOp:translate` -> `translation`，`xformOp:transform:yaw` -> `euler[2]`，`xformOp:scale` -> `scale`。部分小物体的实例 prim 没有 `xformOp:translate`（位置烘在 `Aligned_obj.usd` 的 mesh 顶点中），导出为 `translation: [0.0, 0.0, 0.0]`，属忠实导出。

`full-scene` 模式把 `scene.usd` 整体作为 arena fixture，生成不含 task objects 的 scene-only task yaml。

生成的 yaml 布尔值使用 Python 风格大写（`True` / `False`），脚本内置自定义 YAML dumper。

## 7. 注意事项

- 同一份数据存在于 `InternDataAssets/assets/assets_addition` 与 `workflows/simbox/assets/assets_addition` 两处，修改场景时注意同步。
- `asset_optimization_report.json` 中的 `path` 是生成机器的绝对路径（`/home/mz/...`），只作记录，不能作为加载路径。
- `assets/task_obj/` 顶层散落的 `*_texture.png` 与 `textures/` 子目录不属于对象目录，遍历对象时按目录过滤。
- 场景目录内 `render_image/top_down.png` 与根目录 `render_image/file_<id>__top_down.png` 内容相同，二选一使用。
- 分发单元是 `file_<id>/` 整个目录，工具链接入时不要只取其中一个 JSON 或 USD 文件。
