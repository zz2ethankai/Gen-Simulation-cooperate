## 背景

SimBox 底座导航原本依赖外部 Nav2 栈：nav2/ 目录存放 bridge 与 runtime 实现，docker 内跑独立的 ros2-humble-nav2 容器，通过 action client、TF、时钟与 SimBox 通信。这套栈 reset 后绑定容易失效，容器与 GPU 隔离也复杂。2026-08-07 起改为仓库内 ROS-free 本地导航：navigate skill 不再挂接 Nav2 会话管理器，改用本地 A*（GridAStarPlanner）规划 + Waypoint P 控制器在每个物理周期输出 body twist；底座控制统一走 workflows/simbox/core/mobile/local_base_driver.py。nav2/ 目录整体删除，docker-compose 不再定义 nav2 服务。

现状参数（见代码）：navigate.py 的 runtime_timeout_sec 默认 180.0，output_root 默认 output/local_navigation/skills，map_z_max 默认 1.50（panda_omron_virtual.yaml:74 覆盖为 1.25）；planner map_resolution 0.05，xy/yaw_goal_tolerance 默认 0.10；approach_max 默认 0.65、approach_sample_count 默认 512，新增 approach_armbase_tolerance 0.15、approach_max_refinements 2；is_ready() 恒返回 False；floor 目标只加平移不旋转 yaw；调试产物为 {planned, failed, timeout, succeeded, control_error}.json。地图为运行时二值 ndarray，不落盘。test/unit/test_local_navigation.py 是主要单测。

## 关键机制

导航运行在 Isaac 进程内，navigate skill 的 update()（navigate.py:399）每个物理步被调度一次，链路如下：

1. 首个周期 _begin_plan_impl()（navigate.py:312）：load_or_export_static_map()（local_navigation.py:362）从 workflow canonical cache 获取或经 IsaacStaticMapExporter 导出运行时 `StaticMap`；
2. select_approach_goal()（local_navigation.py:419）用单个 GridAStarPlanner 对全部 approach 候选做中心单元静态检查，plan_to_goals() 一次多目标 A* 搜索（启发式取到所有目标的最小距离，找到 max_solutions 个目标即停），可达者再 build_navigation_plan()，最后按 distance_to_target 取最近候选；
3. build_navigation_plan()（local_navigation.py:347）生成带 yaw 的航点序列：首点 yaw 取实测 start_pose[2]，中间点沿下一段方向，终点取目标 yaw；保留全部网格航点（7f01174 起不再简化）；
4. 每个物理周期 WaypointController.command()（local_navigation.py:316）按当前位姿与航点输出 body twist（先转向后前进，rotate_first_error_rad 内禁直行），navigate.update() 调 driver.set_command(body_vx, body_vy, body_wz)（navigate.py:455）；
5. 位置与 yaw 均进入容差后置 _goal_reached，进入 settle 状态机：持续下发零命令，用 driver.get_actual_twist_body()（local_base_driver.py:220，只读实测 body twist）逐周期判定，连续 settle_consecutive_steps（默认 8）步实测平面速度与 yaw 速率低于 linear/angular_speed_tolerance（默认 0.005）才判成功；超时 runtime_timeout_sec 判 timeout；收尾统一调 driver.finalize_after_navigation()。

## 残留问题与验证边界

- 导航成功标准只依赖目标容差 + 实测 twist 静止，未在物理世界复核到达点的 4WIS 动态稳定性与手臂可达性；无碰撞 overlay 不能替代真实任务验证。
- approach 候选可达性只做中心单元 occupancy + A*，footprint 多边形栅格化已被 3b0b377 移除；2D 图上有效的候选仍可能距台面过近或导致横向接近不可行。
- settle 判定依赖 get_actual_twist_body() 的位姿差分，只在 omron_virtual_base 等虚拟底座 profile 上跑过；ranger_mini_v3 等其它底座 profile 未见导航验证记录（待验证）。
- d59ac03 的 _ensure_local_base_driver_bindings() 与 432c004 的 settle 状态机没有独立单测，依赖场景任务回归（待验证）。
- 7f01174 保留全部网格航点后航点数增加，WaypointController 每周期只消费一个航点，长路径控制延迟与振荡未实测。
- runtime_timeout_sec 超时与 control_error 分支只有失败日志路径，未在真实超时场景下回归（待验证）。
