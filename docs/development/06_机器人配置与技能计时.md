## 背景

技能执行缺少可对比的耗时数据，规划、执行、仿真各段的耗时无法拆分；CuRobo 规划耗时波动大，需要基线。2026-08-11 新增独立 telemetry 模块（skill_timing.py，1261 行新文件），按 skill / phase / category 聚合耗时，并支持前后对比。2026-08-13 修正 PandaOmron TCP 偏移：panda_omron.yaml 与 panda_omron_virtual.yaml 的 tcp_offset 从 0.1043 改为 0.1034，与模型几何一致（panda_omron_virtual.yaml 中 fl_gripper_keypoints.tool_head 同为 0.1034）。

### 五类分类
- SIMULATION_CATEGORY = "simulation"（41）：物理仿真推进耗时，配合 record_simulation_step() 统计 physics_steps 与 simulated_time_sec。
- EXECUTION_CATEGORY = "execution"（42）：运动/控制执行耗时（navigation.execution、motion.<phase>）。
- PLANNER_CATEGORY = "planner"（43）：规划器耗时（simple_generate_manip_cmds、navigation.plan）。
- CUROBO_CATEGORY = "curobo"（44）：CuRobo 规划耗时，template_controller 对查询做 CUDA 同步后按 operation 计时。
- OTHER_CATEGORY = "other"（45）：未归类 phase。
- _CATEGORY_ALIASES（48-63）把 sim/simulate/exec/execute/run/plan/planning/cu_robo 等归一；_normalize_category()（153）小写化、空格转下划线后查表，未命中原样返回，空值归 other。
- _PLANNER_CATEGORIES = {planner, curobo}（47）：planner_sec 是两个分类 total_sec 之和（_planner_duration，1046）。

### summary() 输出字段（1053-1099）
- 基础字段：schema_version（=1）、enabled、successful_skill_count、failed_skill_count、by_skill、by_phase、by_category、planner_sec、curobo_sec、failure_events。
- enabled 时追加：physics_steps / simulated_time_sec（按 skill 聚合求和）、episode_physics_steps / episode_simulated_time_sec（record_episode_simulation_step 的独立计数，用于并发 skill 场景）、simulation_sec、execution_sec、successful_skill（全部成功 skill 的总体聚合）。
- retain_records=True 时追加 completed_skill_records（每次成功 skill 的 skill_name/duration_sec/physics_steps/simulated_time_sec/phases/metadata）。
- 聚合值来自 _DurationAggregate.to_dict()（344）：count、total_sec、mean_sec、min_sec、max_sec、p50_sec、p95_sec、physics_steps、simulated_time_sec。
- exclusive/inclusive 语义：by_phase 的主值（total_sec 等）是 inclusive 时长，另带 exclusive_* 系列（exclusive_total_sec/exclusive_p50_sec 等）；by_category 的主值是 exclusive 时长（不重复计嵌套子 phase），另带 inclusive_* 系列。by_skill 的 _SkillAggregate.to_dict()（416）同时含 total 聚合、phases/categories 子聚合与 simulation_sec/execution_sec/planner_sec/curobo_sec 及 mean/p50。
- p50/p95 用 _percentile()（197）插值计算，样本上限 max_samples（默认 128），样本超限后只更新 total/min/max。

### compare_timing_summaries() 用法（1187-1236）
- 输入两个 summary() 输出，离线比较，不导入仿真包（before/after 先经 json_safe）。
- 顶层比较 metrics = (total, planner, curobo, simulation, execution) 的 mean_sec 与 p50_sec；by_skill 对每个成功 skill 名同样比较（_skill_metric_aggregate 取 skill 聚合内的 categories）。
- 每个值输出 before / after / absolute / delta / ratio（_compare_values，1141）；ratio 在基线为 0 时取 None（前后都为 0 取 1.0）。
- 典型用法：改动前后各跑一组 episode，分别 dump summary()，再用本函数输出 delta/ratio 判断规划耗时是否下降。

### json_safe() 的 duck typing 设计（73-150）
- 模块顶部只导入标准库（contextvars/dataclasses/enum/math/numbers/os/operator/time/pathlib/typing），不导入 NumPy/Isaac，telemetry 在离线测试与轻量进程中可导入。
- 处理顺序：None/str/bool/int/enum → 非有限 float 转 None → numbers.Real 转 float → Path/bytes → dataclass → Mapping → list/tuple/set/frozenset → 通过 item()/tolist() duck typing 转 NumPy 标量/数组、tensor、USD 向量 → 可迭代兜底 → _safe_text。
- _seen 集合防循环引用（命中返回 "<recursive>"）；任何一步失败都 best-effort 兜底，不抛异常。

### enabled=False 时 no-op
- SkillTimingRecorder(enabled=False) 下 skill()/phase() 返回 _NoopPhase（468），不调用 _now()/时钟；test_disabled_recorder_is_a_noop_and_does_not_call_clock 断言 clock.calls == 0。
- summary() 只返回基础字段（schema_version=1、enabled=False、计数 0、空聚合、planner_sec/curobo_sec=0.0、failure_events=[]），不追加 enabled 字段组。
