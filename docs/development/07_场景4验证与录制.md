## 验证判据（run_simbox_task.sh）

### 判定流程
- 环境变量 TASK_CONFIG 必填，LAUNCH_TEMPLATE 默认 configs/de_plan_with_render_template.yaml；GPU_ID / RANDOM_NUM / RANDOM_SEED 先做参数校验（run_simbox_task.sh:28-30），非法参数 exit 2。
- prepare_simbox_run.py 把宿主路径翻译为容器内路径，输出契约：task_container（任务 YAML）、launcher_container（launcher 配置）、launcher_args（含 --load_stage.scene_loader.args.cfg_path 与可选的 --store_stage.writer.args.output_dir）、episode_event_container、debug_output_container。
- 启动前检查：compose 文件存在、docker CLI/compose/daemon 可用（缺任一 exit 3 runtime_unavailable）、docker compose config 能解析镜像（失败 exit 4 start_failed）、本地已有镜像（缺 exit 5 image_missing）。
- 启动后 docker logs -f 落盘到 <metadata>.isaac.log，docker wait 读容器退出码；读不到退出码 exit 125（run_simbox_task.sh:192-197）。SIGINT/SIGTERM 写 status=interrupted 后以 130/143 退出（162-169）。

### 日志 marker 判定规则（run_simbox_task.sh:202-218）
- 容器退出码为 0 时才进入 marker 校验，依次检查：
  1. 日志非空（! -s 判定）；
  2. 含 "Task is successful, mode=plan_with_render"；
  3. 不含 "[LmdbLogger] Episode failed"；
  4. 不含 "Traceback (most recent call last):"。
- 任一项不通过：application_status=application_failed、exit_code=20，并在 stderr 打印 ISAAC_APPLICATION_FAILED 与具体 validation_error。
- 缺 traceback 或有视频不算成功；真实验证还要求 skill snapshots（pick/place 成功检查）与 episode 产物正常，视频不满足判据。

### exit_code 含义
| exit_code | 含义 |
|---|---|
| 0 | 成功（容器退出 0 且通过全部 marker 校验）；DRY_RUN=1 时也返回 0 |
| 2 | 参数非法（GPU_ID / RANDOM_NUM / RANDOM_SEED） |
| 3 | runtime_unavailable（compose 文件、docker CLI/plugin/daemon 不可用） |
| 4 | start_failed（镜像解析失败或 up_simbox_isaac.sh 启动失败） |
| 5 | image_missing（所需镜像本地不存在） |
| 20 | application_failed（marker 校验不通过） |
| 125 | docker wait 失败（读不到容器退出状态） |
| 130 / 143 | SIGINT / SIGTERM（写入 status=interrupted） |

### docker_runtime.json 字段（run_simbox_task.sh:83-92）
- 路径：output/docker_runtime/<task名>-$$/docker_runtime.json（INTERNDATA_DOCKER_METADATA_PATH 可覆盖），同目录 .isaac.log 为容器日志。
- 字段：status（starting / running / finished / application_failed / dry_run / runtime_unavailable / start_failed / image_missing / interrupted）、exit_code、stack_id、compose_project、isaac_container、host_gpu_id、task_container、isaac_log_path。
- 导航点叠加图：export_task_nav_points_overlay.py 生成 Isaac-free top-down 图，只作设计证据；无碰撞的 overlay 不能证明 4WIS 稳定性或机械臂可达性。

## 工作点规划（三阶段）

### 接口
- plan_workspace_layout.py 生成离线候选（--task <simbox_task.yaml> --target <object> --output-dir），validate_workspace_candidates.py 验证（--manifest candidates.json --gpus ... --max-pick-candidates 3）。
- 采样默认值只在 planner schema 定义一次：min_radius_m 0.45、max_radius_m 1.05、candidate_count 24、preferred_radius_m 0.75、sequence golden_angle；候选 ID 固定 annulus_000 ... annulus_023，对 r² 均匀采样使候选在环形面积上均匀分布，相同输入得到相同坐标与排序。

### 阶段一 · Geometry
- 输出：geometry_candidates；通过点按 abs(radius - preferred_radius) → candidate_id 排序。
- 失败判定：全部候选的旋转 footprint OBB 与家具/墙相交，或四角不在 floor 边界内 → status=no_geometry_candidate。可移动刚体在 floor 上仍可生成底盘候选，但只代表底盘可放置，不代表地面 Pick 可达。
- 运行坐标写入（compiler）：robots[0].euler[2]、source_regions.robot_initial_region、regions[robot].random_config.pos_range、metadata.workspace_candidate；源 task/arena 只读。

### 阶段二 · CuRobo Probe
- 输出：curobo_results；GraspPlanEvaluator 是唯一抓取轨迹筛选实现，Probe 与 Pick 共用，禁止复制判断逻辑。
- 失败判定：joint_success_count（同一抓取标注 pre-grasp 与 grasp 两段都成功的轨迹数）为零直接失败，不允许回退到第一个/最后一个抓取标注；attach_collision_prim_paths 任一路径在 native v2 world_cfg 中按精确 path 查不到（get_obstacle）→ status=blocked（ATTACH_PRIM_NOT_IN_CUROBO_WORLD），这是候选无关错误，一旦发现终止后续点位。
- 每个底盘候选用独立 Isaac 进程，左右臂在同一进程分别输出 JSON；Probe 不移动机器人、不写 LMDB/视频。候选排序：joint_success_count 降序 → selected_grasp_score 升序 → abs(radius - 0.75) 升序 → candidate_id。

### 阶段三 · Pick 验证
- 输出：pick_attempts；使用最小官方写法与 Probe 推荐手臂，不新增成功谓词。
- 失败判定：Pick.is_success() 未通过，或日志无 "Task is successful"、episode event 非 success、目录为 fail_*、本轮未产生新 meta_info.pkl、本轮未产生新 lmdb/data.mdb → status=no_pick_success（前三个 CuRobo 点位均未通过）。
- seed 0 成功后继续验证 seed 1、2，标记 3/3 stable、2/3 partially_stable、unstable。

### candidates.json 状态机
- 唯一状态文件，字段：version、target、sampling、geometry_candidates、curobo_results、pick_attempts、selected_candidate、status、failure_code。
- 状态：geometry_ready（存在底盘几何候选）→ no_geometry_candidate / no_curobo_candidate / no_pick_success / blocked / success。
- 任何阶段成功不能代替后续阶段：CuRobo 成功不表示物体能被夹住；blocked 需要修资产/标注/attach 契约，而不是换点位。
